百万级数据高性能编辑 ​

极简用法只需两步：

  1. 表格开启 :performance-edit="true"
  2. 需要编辑的列设置 performanceEdit: true
vue
<w-list-table :columns="columns" :data="data" :performance-edit="true" />
ts
const columns = [
    { field: "name", title: "名称" },
    { field: "amount", title: "金额", performanceEdit: true }
];

开启后，非编辑状态由 Canvas 绘制 Input 外观，整张表同一时间只挂载一个真实 Input。输入值会立即写回源 data，不会因为每次输入重新设置整表数据。

高性能编辑默认开启键盘导航：方向键按对应方向跳到下一个可编辑单元格，Enter 等同于 →。无需再配置 VTable 的 moveEditCellOnArrowKeys。

动态切换静态外观 ​

appearance 可以按单元格返回三种结果：false 使用普通文本，'input' / 'Input' 恢复完整默认 Input 外观，样式对象只覆盖默认外观中的差异项。

下面的独立示例通过按钮修改指定行、指定列的模式，再调用 refreshData() 重绘 Canvas。它同时演示了动态 editable：普通文本模式不可编辑，另外两种模式仍可进入编辑。

动态切换 PerformanceEdit 单元格外观
按钮切换指定行列的普通文本、默认 Input 和自定义样式
<template>
    <div>
        <a-space style="margin-bottom: 12px" wrap>
            <a-tag color="blue">Input：内置默认外观</a-tag>
            <a-tag>普通文本：appearance = false</a-tag>
            <a-tag color="orange">自定义：只覆盖差异样式</a-tag>
        </a-space>

        <a-space style="margin-bottom: 12px" wrap>
            <a-button @click="cycleAmountAppearance">
                切换第 2 / 4 / 6 行销售额外观
            </a-button>
            <a-button @click="cycleDiscountAppearance">
                切换第 1 / 3 / 5 行折扣外观
            </a-button>
            <a-button @click="resetAppearance">恢复默认 Input 外观</a-button>
        </a-space>

        <div style="height: 460px">
            <w-list-table
                ref="tableRef"
                :columns="columns"
                :data="data"
                :is-page="false"
                :performance-edit="true"
                :vtable-options="{ defaultRowHeight: 42 }"
            />
        </div>
    </div>
</template>

<script setup lang="ts">
import { ref } from "vue";
import type {
    ExtendListTableColumn,
    PerformanceEditAppearanceValue
} from "@wlink/antd-next";

type AppearanceMode = "input" | "text" | "custom";

interface RowData {
    id: number;
    product: string;
    amount: string;
    discount: string;
    amountMode: AppearanceMode;
    discountMode: AppearanceMode;
}

const tableRef = ref<any>();
const data = ref<RowData[]>(
    Array.from({ length: 18 }, (_, index) => ({
        id: index + 1,
        product: `商品 ${String(index + 1).padStart(4, "0")}`,
        amount: String((index + 1) * 100),
        discount: String((index % 8) + 1),
        amountMode: "input",
        discountMode: "input"
    }))
);

const modeText: Record<AppearanceMode, string> = {
    input: "默认 Input",
    text: "普通文本",
    custom: "自定义样式"
};

const resolveAppearance = (
    mode: AppearanceMode,
    color: "orange" | "blue"
): PerformanceEditAppearanceValue => {
    if (mode === "text") return false;
    if (mode === "input") return "Input";

    return color === "orange"
        ? {
              backgroundColor: "#fff7e6",
              borderColor: "#fa8c16",
              color: "#d46b08"
          }
        : {
              backgroundColor: "#e6f4ff",
              borderColor: "#1677ff",
              color: "#0958d9",
              textAlign: "center"
          };
};

const nextMode = (mode: AppearanceMode): AppearanceMode =>
    mode === "input" ? "text" : mode === "text" ? "custom" : "input";

const updateRows = (ids: number[], field: "amountMode" | "discountMode") => {
    data.value.forEach(row => {
        if (ids.includes(row.id)) row[field] = nextMode(row[field]);
    });
    // performanceEdit 不深度监听整表；业务原地修改后主动重绘 Canvas。
    tableRef.value?.refreshData();
};

const cycleAmountAppearance = () => updateRows([2, 4, 6], "amountMode");
const cycleDiscountAppearance = () => updateRows([1, 3, 5], "discountMode");

const resetAppearance = () => {
    data.value.forEach(row => {
        row.amountMode = "input";
        row.discountMode = "input";
    });
    tableRef.value?.refreshData();
};

const columns: ExtendListTableColumn[] = [
    { title: "行号", field: "id", width: 70, fixed: "left" },
    { title: "商品", field: "product", width: 150, fixed: "left" },
    {
        title: "销售额",
        field: "amount",
        width: 160,
        performanceEdit: {
            editable: ({ record }) => record.amountMode !== "text",
            appearance: ({ record }) =>
                resolveAppearance(record.amountMode, "orange")
        }
    },
    {
        title: "折扣",
        field: "discount",
        width: 160,
        performanceEdit: {
            editable: ({ record }) => record.discountMode !== "text",
            appearance: ({ record }) =>
                resolveAppearance(record.discountMode, "blue")
        }
    },
    {
        title: "销售额模式",
        field: "amountMode",
        width: 130,
        formatter: ({ value }: { value: AppearanceMode }) => modeText[value]
    },
    {
        title: "折扣模式",
        field: "discountMode",
        width: 130,
        formatter: ({ value }: { value: AppearanceMode }) => modeText[value]
    }
];
</script>

与 slots 编辑的区别 ​

模式适用场景渲染方式
performanceEdit大数据量、大量可编辑单元格Canvas 外观 + 单实例 Vue Input
slots复杂展示、按钮、任意 VNode可见单元格挂载 Vue DOM

performanceEdit 默认关闭，不会改变原有 slots 行为。同一列同时配置 slots 和 performanceEdit 时，优先保留 slots 渲染。

如需关闭高性能编辑的默认键盘导航：

vue
<w-list-table :performance-edit="{ keyboardNavigation: false }" />

外部自定义复合 Input ​

一个单元格内需要一个或多个业务 Input 时，使用 createVuePerformanceEditAdapter 注册外部适配器。组件不限制 Input 的来源，示例使用的是外部 ant-design-vue 的 Input，不是 ListTable 内置 Input。

下面的示例包含两个可编辑列：第一列始终只有一个外部 Input；第二列根据每行业务数据，真实地渲染一个或两个 Input。其中还混合了第二个 Input 禁用的行，用于验证复杂导航。

先区分两个容易混淆的配置：

配置出现时机负责内容是否创建 DOM
render当前单元格进入编辑状态返回真正的外部 Vue Input是，只挂载当前编辑单元格
cellRender单元格未编辑时用 Canvas 画出 Input 外观否

createInputCellRender 和 createInputGroupCellRender 都是给 cellRender 使用的 Canvas 外观辅助函数，不是真正的 Input 组件。

  • 主列字段通过 setValue(value) 更新。
  • 同一行的其他字段通过 setRecordValue(field, value) 更新。
  • 非编辑态使用 createInputGroupCellRender 绘制多个 Input 外观，不挂载 DOM。
  • 整张表仍然只挂载当前编辑单元格内的这一组真实组件。

复合编辑器的默认导航规则：

按键复合单元格内的行为
Enter / →进入同格下一个可用控件；没有时进入下一可编辑单元格
←进入同格上一个可用控件；没有时进入上一可编辑单元格
↑ / ↓切换行，并尽量保持当前控件位置

disabled、readonly、隐藏控件、aria-disabled="true" 和 tabindex="-1" 会自动跳过。如果业务组件的真实输入节点不是标准元素，可通过适配器的 inputSelector 指定选择器。

appContext 由 WListTable 自动获取并注入，用于让外部组件继承 Ant Design Vue ConfigProvider、全局组件等上下文。使用 createVuePerformanceEditAdapter 时不需要、也没有参数要求你手动传递它。

外部动态复合 Input
100,001 行；两个编辑列，复合列按行业务条件渲染 1 / 2 个 Input
<template>
    <div>
        <a-space style="margin-bottom: 12px" wrap>
            <a-tag color="purple">100,001 行</a-tag>
            <a-tag color="blue">外部 Ant Design Vue Input</a-tag>
            <a-tag>2 个可编辑列</a-tag>
            <a-tag color="orange">复合列按行渲染 1 / 2 个 Input</a-tag>
            <span v-if="lastChange">
                最近修改：第 {{ lastChange.id }} 行 {{ lastChange.field }} =
                {{ lastChange.value }}
            </span>
        </a-space>

        <div style="height: 520px">
            <w-list-table
                :columns="columns"
                :data="data"
                :is-page="false"
                :performance-edit="performanceEdit"
                :vtable-options="{ defaultRowHeight: 42 }"
                @cell-value-change="onCellValueChange"
            />
        </div>
    </div>
</template>

<script setup lang="ts">
import { h, onMounted, ref, shallowRef } from "vue";
import { Input } from "ant-design-vue";
import {
    createInputCellRender,
    createInputGroupCellRender,
    createVuePerformanceEditAdapter
} from "@wlink/antd-next";
import type {
    ExtendListTableColumn,
    PerformanceEditConfig
} from "@wlink/antd-next";

interface RowData {
    id: number;
    product: string;
    suggestedQty: string;
    planQty: string;
    previousPlanQty: string;
    inputMode: "single" | "double" | "double-disabled";
    description: string;
}

const inputStyle = { width: "100%", height: "100%" };

const singleInputAdapter = createVuePerformanceEditAdapter({
    render: ({ value, setValue }) =>
        h(Input, {
            value,
            style: inputStyle,
            placeholder: "建议补货",
            "onUpdate:value": setValue
        }),
    cellRender: createInputCellRender({ textAlign: "right" })
});

const compositeInputAdapter = createVuePerformanceEditAdapter({
    render: ({ value, setValue, setRecordValue, cellContext }) => {
        const record = cellContext?.record as RowData | undefined;
        const inputs = [
            h(Input, {
                value,
                style: inputStyle,
                placeholder: "本期计划",
                "onUpdate:value": setValue
            })
        ];

        // 业务条件决定该行是否真正渲染第二个 Input，不是用 disabled 伪装单输入。
        if (record && record.inputMode !== "single") {
            inputs.push(
                h(Input, {
                    value: record?.previousPlanQty ?? "",
                    style: inputStyle,
                    disabled: record?.inputMode === "double-disabled",
                    placeholder: "历史补货",
                    "onUpdate:value": (nextValue: string) =>
                        setRecordValue("previousPlanQty", nextValue)
                })
            );
        }

        return h(
            "div",
            {
                style: {
                    display: "grid",
                    gridTemplateColumns: `repeat(${inputs.length}, minmax(0, 1fr))`,
                    gap: "6px",
                    width: "100%",
                    height: "100%"
                }
            },
            inputs
        );
    },
    cellRender: createInputGroupCellRender({
        items: ({ record }: { record: RowData }) => {
            const items = [
                {
                    value: record?.planQty,
                    placeholder: "本期计划",
                    disabled: false
                }
            ];
            if (record?.inputMode !== "single") {
                items.push({
                    value: record?.previousPlanQty,
                    placeholder: "历史补货",
                    disabled: record?.inputMode === "double-disabled"
                });
            }
            return items;
        }
    })
});

const performanceEdit: PerformanceEditConfig = {
    adapters: {
        singleInput: singleInputAdapter,
        compositeInput: compositeInputAdapter
    }
};

const columns: ExtendListTableColumn[] = [
    { title: "行号", field: "id", width: 70, fixed: "left" },
    { title: "商品信息", field: "product", width: 140, fixed: "left" },
    {
        title: "建议补货",
        field: "suggestedQty",
        width: 130,
        performanceEdit: "singleInput"
    },
    {
        title: "补货计划 / 历史补货",
        field: "planQty",
        width: 230,
        performanceEdit: "compositeInput"
    },
    {
        title: "说明",
        field: "description",
        width: 260
    }
];

const data = shallowRef<RowData[]>([]);
const lastChange = ref<{
    id: number;
    field: string;
    value: unknown;
}>();

const onCellValueChange = ({ field, changedValue, record }: any) => {
    lastChange.value = {
        id: record.id,
        field: String(field),
        value: changedValue
    };
};

onMounted(() => {
    data.value = Array.from({ length: 100_001 }, (_, index) => {
        const inputMode = (["single", "double", "double-disabled"] as const)[
            index % 3
        ];
        const description = {
            single: "该行复合列只有 1 个 Input",
            double: "该行有 2 个，均可编辑",
            "double-disabled": "该行有 2 个，第二个禁用"
        }[inputMode];

        return {
            id: index + 1,
            product: `商品 ${String(index + 1).padStart(6, "0")}`,
            suggestedQty: String((index % 80) + 20),
            planQty: String(index % 100),
            previousPlanQty: String(index % 20),
            inputMode,
            description
        };
    });
});
</script>

键盘导航 ​

设置 keyboardNavigation 为 true，使用方向键 ↑ ↓ ← → 和回车键在包含可输入元素的单元格之间跳转，跳转后自动聚焦并全选内容。可输入元素包括 input、textarea、select、[contenteditable] 等。

无需在列上额外标记，组件会自动检测单元格内是否存在可输入元素来判断是否可跳转。

按键行为
↑向上移动到同列上一个可输入单元格
↓向下移动到同列下一个可输入单元格
←向左移动到同行上一个可输入单元格
→向右移动到同行下一个可输入单元格
Enter等同于 →

PerformanceEdit 外部适配器 ​

最小完整用法 ​

下面是一个外部 Ant Design Vue Input 的最小适配器。注册名 amountInput 必须与列上的 performanceEdit: "amountInput" 一致。

const amountInputAdapter = createVuePerformanceEditAdapter({

const performanceEdit = {

常见问题 ​

先按页面上看到的现象查找：

现象先这样处理
点击一行 checkbox 有卡顿确保 columns、vtableOptions、checkboxConfig 不会因勾选而重新生成；不要在勾选事件中调用 refreshData()
设置了 checkedKeys，但某行没有显示勾选检查该行是否被 checkboxConfig 设为不可选；当前数据中不可选的 key 会被自动移除
删除一行后，其他行的勾选也没了检查删除方法是否重置了整个 checkedKeys，以及 checkboxField 在数据更新前后是否保持不变
恢复一行后，该行没有自动勾选确认删除时是否同时移除了该行 key；如果已移除，恢复时需要把 key 一起恢复
修改了行数据，表格没有变化deepWatchData=false 时，批量修改完后调用一次 refreshData()
Input 插槽每输入一个字符都卡顿如果 Input 直接修改 row[field]，设置 deepWatchData=false；大量 Input 再考虑改为 performanceEdit
百万行示例流畅，自己的几千行表格却很慢行数不是唯一因素；检查列数、自动列宽、多选、Vue 插槽和响应式数据方式

为什么百万行示例流畅，几千行宽表反而可能很慢？ ​

虚拟滚动只绘制当前看到的区域，但表格初始化仍要准备列、选择状态和数据索引。百万行示例使用少量固定宽度列、shallowRef 和 Canvas 编辑；一个包含很多列、checkbox、按钮插槽和自动列宽的表格，每行需要处理的内容更多。

数据量较大时依次检查：

  1. 数据数组使用 shallowRef，避免把每个单元格字段都转成 Vue 深层响应式。
  2. 已知列宽时使用 width；不要让大量列在首次进入时根据整份数据推算宽度。
  3. 大量可编辑单元格使用 performanceEdit，普通文字使用原生列；只把按钮、Tag 等少量复杂内容放进 slots。
  4. 编辑场景设置 deepWatchData=false。表格外批量原地修改后，只调用一次 refreshData()。
  5. columns、vtableOptions、actionProps 和 checkboxConfig 使用稳定引用，不要在模板更新时反复创建。

开启多选但没有任何预选行时，ListTable 不会逐行写入“未选中”状态；已有的 checkedKeys 仍会按稳定的 checkboxField 恢复。

点击单行 checkbox 仍然卡顿，怎么检查？ ​

单行勾选时，ListTable 只更新该行的 checkbox、高亮、checkedKeys 和 checkedRows。先检查下面三项：

  1. 勾选回调中只更新选中数据，不要同时重建 data、columns 或调用 refreshData()。
  2. 不要在模板中直接写会每次生成新对象的表格配置。
  3. 检查侦听 checkedKeys 的代码中是否还有汇总、请求或遍历整份数据的操作。

不推荐：

vue
<w-list-table
    :vtable-options="{ rowHeight: 40 }"
    @checkbox-change="tableRef.refreshData()"
/>

推荐：

vue
<w-list-table
    v-model:checked-keys="checkedKeys"
    :vtable-options="vtableOptions"
/>
ts
const vtableOptions = { rowHeight: 40 };

表头全选、取消全选、树形级联选择会检查多行；替换整份 data 或调用 refreshData() 会重新同步表格数据。这些操作比点击单行耗时更多。

为什么设置 [2, 4]，最后 checkedKeys 只有 [4]？ ​

如果 key 2 对应的行被 checkboxConfig 设为不可选，该行当前不会渲染 checkbox。ListTable 会把 2 从选中结果中移除，并同步更新：

  • checkedKeys 为 [4]。
  • checkedRows 只包含 key 4 的行。
  • getCheckboxRecords() 只返回 key 4 的行。
  • 只有 key 4 的行显示选中高亮。

如果某个 key 在当前 data 中找不到，组件会保留它，用于分页或筛选后恢复勾选。

删除和恢复行时，怎样保持选中？ ​

先确认删除方式：

行真的从 data 中移除 ​

如果恢复后需要继续选中，删除时保留该行的 key。该 key 暂时不在当前数据中，不会出现在 checkedRows 里；原行以相同 key 恢复到 data 后，checkbox 会恢复选中。

ts
const removedRow = rows.value.find(row => row.id === id);
rows.value = rows.value.filter(row => row.id !== id);
// checkedKeys 保持不变

// 恢复
rows.value = [...rows.value, removedRow];

如果删除后不需要再选中，只移除该行的 key，不要清空整个数组：

ts
checkedKeys.value = checkedKeys.value.filter(key => key !== row.id);

行仍在 data 中，只是被标记为删除 ​

如果 checkboxConfig 让被标记的行变成不可选，ListTable 会从 checkedKeys 移除该行 key。如果恢复时还要重新选中，需要在标记前记住它是否已选，恢复时再把 key 加回 checkedKeys。

如果恢复一行后所有勾选都消失，逐项检查：

  1. 恢复方法里是否有 checkedKeys.value = []。
  2. 更新数据时是否用新数组覆盖了原有 checkedKeys。
  3. checkboxField 是否使用稳定且唯一的字段。
  4. 恢复前后 key 的类型是否一致，例如不要从数字 1 变成字符串 "1"。

原地修改行数据后，为什么表格没有变化？ ​

更新方式处理方式
偶尔修改某个行字段保持默认的 deepWatchData=true，组件会自动刷新
一次修改很多行设置 deepWatchData=false，全部修改完后调用一次 refreshData()
直接替换 data 数组无论 deepWatchData 是否开启，都会自动同步
使用 performanceEdit表格内编辑会直接写回数据；在表格外批量修改后，调用一次 refreshData()
vue
<w-list-table
    ref="tableRef"
    :data="rows"
    :deep-watch-data="false"
/>
ts
function updateManyRows() {
    rows.value.forEach(row => {
        row.amount = calculateAmount(row);
    });
    tableRef.value?.refreshData();
}

不要在循环内调用 refreshData()，否则表格会被反复刷新。

为什么不要在模板中直接创建表格配置？ ​

下面的写法会在页面每次重新渲染时生成新对象：

vue
<w-list-table
    :action-props="{ width: 70 }"
    :vtable-options="{ rowHeight: 40 }"
/>

当勾选、输入或其他状态变化引起页面重新渲染时，新的配置对象可能让 VTable 重新应用整份配置。改成稳定引用：

vue
<w-list-table
    :action-props="actionProps"
    :vtable-options="vtableOptions"
/>
ts
const actionProps = { width: 70 };
const vtableOptions = { rowHeight: 40 };

columns、checkboxConfig、form 也应保持稳定引用。如果配置依赖响应式数据，使用 computed。

rowKey 和 checkboxField 应该怎么设置？ ​

两者可以使用同一个唯一 ID：

vue
<w-list-table
    row-key="id"
    checkbox-field="id"
    v-model:checked-keys="checkedKeys"
/>
  • rowKey 用于识别每一行、复用插槽内容和写回编辑值。
  • checkboxField 决定 checkedKeys 中保存什么值。

这两个字段的值必须唯一、稳定，且类型不变。不要使用数组下标、随机数，也不要每次刷新数据时重新生成。

分页或筛选后，checkedKeys 和 checkedRows 为什么数量不一样？ ​

  • checkedKeys 可以保留当前 data 中没有的 key。
  • checkedRows 只包含当前已加载的完整行数据。
  • 表头全选只会选择当前已加载的行，不会自动选中还没有加载的其他页。

因此，分页后看到 checkedKeys.length 大于 checkedRows.length 不代表选中丢失。切回原页或让该行重新出现时，相同 key 会恢复勾选。

大量 Input 输入卡顿，应该使用哪种渲染方式？ ​

如果列插槽中的 Input 直接修改行字段，先关闭数据深度监听：

vue
<w-list-table
    :data="rows"
    :deep-watch-data="false"
/>
ts
// Input 的 onUpdate:value / v-model 会直接更新当前可见单元格，
// 不需要每输入一个字符都让表格重新接收全部 rows。
row[field] = value;

替换整个 rows 数组时，表格仍会自动更新。如果代码在表格外原地批量修改了很多行，修改完成后调用一次 refreshData()。

内容使用方式
大量单 Input 或复合 InputperformanceEdit
按钮、Tag、状态展示等少量复杂内容slots
普通文本、数字、格式化结果VTable 原生列配置

slots 会为当前可见单元格创建 Vue DOM。当可见行和 Input 列都较多时，输入、滚动和重新渲染都会变慢。performanceEdit 使用 Canvas 显示非编辑状态，并且同一时间只挂载当前正在编辑的输入组件。
